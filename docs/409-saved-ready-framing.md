# Saved restoration READY framing

The shared native I/O layer provides the bounded `sc-saved-restoration-ready-v2`
metadata frame for the forthcoming two-phase process exchange. A live
`DispatchedSavedRestoration` emits it only while unattempted, in its actual native
process, under its captured empty owner and after reverifying the original native
stage, source, audit, planned intent and staged bytes. Encoding does not consume
publication permission, create canonical media or adopt the saved manifest.

The parent decoder requires its original private dispatch ticket, current
serialized owner and independently observed child PID. The exact flat ASCII JSON
contains only protocol, workerPid and a lower-case hex planned record. Unknown,
duplicate, nested, missing, wrongly typed, non-ASCII, trailing and oversized input
refuses. The record codec and original dispatch check phase, project, asset,
content, fresh operation, source/preparation/staging context and native writer
identity. The 32 KiB frame/parser bank and decoded record storage are admitted
before allocation; cancellation and ledger scope remain enforced. Decoding
returns admitted planned metadata, never native owners or publication permission.
An old READY frame alone cannot reconstruct a stage or qualify an exited child.

This is framing groundwork, not an enabled controller publication route. The v1
stage worker still requires EOF before work and exits without publication. The
next v2 process integration must retain the same live child stage while awaiting
permission, bound its request/READY/permit/terminal framing and deadlines, reject
extra or duplicate frames, serialize permission with real parent cancel/close,
keep native pins until actual retirement, and report ambiguous visibility
conservatively. Independent canonical verification after native handle retirement
and explicit strict Open/adoption remain required. No GUI, installer, release or
full recovery claim follows from a READY codec test.

The existing Linux/native Windows qualification, GPL/source, processing, import,
equipment, content, all-Europe localization and frozen product-reference gates
remain unchanged. Historical deliveries remain preserved while shared development
advances.
