## Preview builder admission

Both builders retain their existing v4 helper qualification. A source tree with
the protected renderer also requires `--protected-warp-qualification`, using the
v5 producer in `tests/protected_warp_worker_tests.py`. Produce it with the actual
helper and parent verifier from the native build to be packaged, plus the scoped
prototype. Set `SC_PROTECTED_WARP_QUALIFICATION` or pass `--qualification`.
Committed clean source and a fresh report path are required by the producer.
The prototype is a qualification tool and is not an installed payload.

The shared validator checks source commit/tree and the packaged helper SHA256,
native platform, actual process records, success/refusal counts, exact typed
coordinates and normalized owner/span/point identity, complete duration and
resource policy, and all 18 full-PCM prototype comparison identities. It
independently reconstructs canonical cache-key hashes. The Linux builder hashes
the actual input helper; Windows binds the exact single deployment manifest row.
Missing or stale receipts refuse before creating a package output directory.
The prepared receipt records the v5 report hash and a bounded scope summary.

Windows source-mutation evidence checks denied writes while its approved reader
holds the file, then rejects a stale hash before opening a job. Linux observes
changed source after ready. These distinct observations remain explicit. Both
platform receipts must retain `nativeAudio=false` and `fullQualityQualified=false`.

These are consistency checks on maintainer-generated observations. They do not
authenticate a malicious receipt, replay DSP, qualify an installed application,
or replace GPL source, dependency, native audio and processing-quality gates.
The [retained fixtures](../tests/fixtures/protected-warp-qualification/README.md)

scope inflation, missing/stale helper/source, incomplete/crashed jobs, changed

## Apply and audition follow verified inputs

After Render, editing duration, pitch, formants, context or marker owners/positions
makes Apply and audition unavailable until the controls match the verified inputs
or a new result is rendered. The status asks the user to render again. Canonically
equivalent duration fractions remain equivalent. Restoring the original inputs
reuses the retained verified result; it does not start a new job or edit history.

Comparison is cached until a control or immutable selection changes. Temporary
marker copies reserve payload credit before allocation and retire outside audio
callbacks. No graph planning or file I/O occurs in this comparison. A result-free
state releases the cached selection. Temporary payload refusal leaves actions disabled
and retries on subsequent refresh, allowing released credit to recover. Callback-time project/clip guards remain.
Audition still requires explicit Stop before Apply or another Render.

The real Qt regression first fails with edited marker targets admitting stale
verified audio. It then checks disabled actions, unchanged project/playback,
restoring targets, source edits, adding/removing owners and audition lifetime.
The constant/context workflow additionally exercises pitch, formants, context
and canonical duration fractions. End-to-end installed Linux/Windows coverage
and recovery remain the next gate before delivering this workflow in a preview.
