# ADR113: explicit verified publication of recorded loop windows

Status: accepted for partial desktop audio-loop workflow.

Keep automatic recording mode independent from saved loop locators. Freeze the
mode/pass count and original source context at preparation. Publish original loop
context between raw-writer startup and native activation, outside real time.

After joined capture, retain an immutable complete original source bundle for an
explicit paged preview. Pass count does not allocate an equivalent inventory of
workers or GUI rows. A page is a memory-budgeted inactive take edit with a stable
project-epoch guard, independently verified original media/context/clock origins,
explicit partial policy and semantic history. Source windows address the full raw
assets. Save and comp selection remain explicit.

Using ordinary automatic audible attachment would discard the pass-selection
workflow. Reusing manual complete-group admission with fabricated trimmed raw
receipts would lose original provenance. Neither alternative is adopted. Repeated
page publication can reuse full assets but completion must use request correlation,
not a global last-attached-asset comparison. Allowed scalar edits during disk
verification are preserved. Errors retain raw jobs and the pending preview.

The normal Windows duplex owner and native/installed loop qualification remain
separate required work. See [checkpoint176](../176-desktop-loop-recording.md).
