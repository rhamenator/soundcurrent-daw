# ADR 191: Require actual nominal provenance before protected comp adoption

2026-10-15. Status: qualified engine/model workflow for the tested original
integer-clock cases; desktop entry and native runtime confirmation pending.

Use the original owned nominal stretch jobs and independently verified receipts
before assembling protected spans. Do not treat an in-process nominal fixture
with a placeholder render key as publication evidence. Preserve original context
and semantic warp when reconstructing nominal requests, and assert both sides'
processor identities in mixed pairs. Existing-media sides produce no new jobs.

Keep one shared assembly/publication/model path. Verify complete PCM separately
from allowed edit scopes. Exercise actual protected/protected, protected/uniform
and protected/existing-media pairs through saved trusted references, atomic
completion, canonical Undo/Redo/save/reopen and shared playback/export.

Test abrupt process retirement at file-close, first-file-publication and
pre-completion boundaries. Fresh-process inspection must observe the expected
published-file count, no completion or accepted output, and no resume/overwrite.
Use explicit abrupt-exit reports and distinguish this from power-loss durability.
Retain original inputs and partial output as failure evidence.

The original nominal protocol still does not bind its executable digest. Record
the actual binary called by the acceptance driver without claiming a protocol
property it lacks. No dependency or license change. No independent sound-quality,
physical audio, desktop interaction or installed delivery claim follows from
these tests. See [checkpoint 303](../303-protected-comp-assembly.md).
