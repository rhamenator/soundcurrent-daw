# ADR-027: immutable desktop arms and atomic verified take groups

Date: 2026-10-06. Status: accepted for the scoped M2d3 workflow.

## Context

The production duplex owner already joins independent raw writers, but the
selected-track desktop handoff cannot express an immutable armed set, route every
packed channel or preserve grouped canonical history. Treating one higher EQ
receipt as proof of every lane would falsely claim whole-model application.

## Decision

- Capture the full accepted canonical prefix, explicit arm IDs and finite range
  before preparation. Keep the saved master plan and input packing immutable.
  Inspector selection and canonical order changes do not rebind capture.
- Extend the existing non-RT recording endpoint seam and worker; no virtual call
  enters audio. Use the existing PipeWire duplex owner and framework-free engine.
- Save explicit input intent by track/local channel and output intent by master;
  never infer defaults. Keep preparation-time monitoring policy separate from
  live scalar/enable reconciliation and always require playback output routes.
- Track required/applicable receipts by prepared lane/generation. Queue Full
  retains the accepted bundle's exact suffix; all participating receipts must
  arrive before the whole model is reported applied.
- Retain successful joined receipts as one pending group while preserving failed
  lane errors/jobs separately. Verify every inactive finalized journal/extent/hash
  off the control/GUI/audio threads, then replay the group against the latest
  canonical model and adopt one history entry. Any invalid member denies all.
- Native joins precede disk joins; group verification/admission precedes active
  Save/close. Preserve initiating failure diagnostics and partial job directories
  without implying that a journal-less directory can be recovered.
- Qualify real engine/disk workflows through a synthetic endpoint, then use
  independent owned native GUI sources/sink and output oracles. Linux/Windows
  qualification, localization and all frozen workflow/quality gates remain distinct.

## Consequences

The desktop can record armed raw tracks with existing-file playback and grouped
Undo/Redo while preserving live edits, failed-lane recovery material and raw media.
The 1..256 and aggregate payload admission bounds remain unchanged. There is no
new dependency/license change. Long-duration/load/physical/native Windows,
monitoring Auto/punch/loop/takes/comping and full product parity remain required.
