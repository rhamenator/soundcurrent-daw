# ADR 192: Select protected desktop rendering from original semantic state

2026-10-15. Status: implemented and locally exercised; current native Windows
confirmation and installed delivery pending.

Desktop transition preparation selects the explicit protected-pair policy when an
original nominal clip carries semantic warp protection. It preserves the uniform
selection format for ordinary uniform clips. Resolve the original nominal state
through regeneration metadata when present; do not classify from the current
assembled artifact or a slope heuristic. Unsupported protected history/timing
must fail in the protected adapter before immutable pair/assembly publication.
Never silently retry uniform DSP after a protected refusal.

Keep creation, saved references, isolated rendering, review and explicit undoable
Apply on the existing shared controller and engine path. New acceptance inputs
must have real owned nominal provenance and cover protected/protected at three
rates, protected/uniform and protected/existing media. Require no active audio
change before Apply, canonical Undo/Redo/save/reopen/export, asynchronous refusal
and close paths, exact producer identities and retired child processes.

Memory cleanup evidence must observe the window's actual project ledger, not an
options ledger replaced during construction. Require positive reservations while
the project is open and zero after window/controllers/snapshots are destroyed.
Correct misleading derived claims without rewriting original retained evidence.

No new dependency, license, translation string or product quality claim. Existing
integer/same-clock limits remain admission constraints awaiting required broader
implementation. See [checkpoint 304](../304-protected-desktop-transitions.md).
