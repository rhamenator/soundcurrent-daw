# S4 capture, disk writing and recording recovery

Implemented headless components: `SoundCurrent::Capture` (Qt/OS/library-free transport), `SoundCurrent::Media` (disk-side libsndfile/crypto/files), `RecordingWorker` and `sc-record-tool`. Linux executes the fixtures. Windows builds the same components and tests against a pinned locally cross-built DLL; native execution remains unverified. S4 reliability qualification is incomplete; [S5](14-native-audio-contract.md) now adds native owned-source evidence, device origin and terminal reasons.

## Ownership and real-time bounds

Construct/admit `CapturePipe` off RT. It touches one float32 allocation divided into **32 slabs**, with free and ready SPSC token queues of capacity64. Default slab sizing reserves at least two seconds at the negotiated rate; explicit sizes256–65536 frames are available. Rates8–384 kHz, channel layouts1–256, and callbacks1–65536 frames are admitted only within the chosen memory budget (default128 MiB, maximum256 MiB). Admission failure is explicit; arbitrary channel count does not promise that every rate/channel combination fits every budget.

One audio owner calls `push` with planar views and engine-frame timestamps. It copies to interleaved preallocated slabs, aggregating small callbacks without emitting one disk token per callback. Packets carry uint64 sequence, int64 first frame, count and slab index. Views expire when the disk owner releases the exact acquired token. A slab cannot return to audio while disk/hash work still reads it. Only one disk view may be acquired at once.

No allocation/free, file operations, worker wakeup syscall, logging, blocking lock or spinning occurs in `push`/`finish`. The callback bound is the admitted sample count plus slab transitions; deadline qualification on native devices is still required. The default pool is not an mlock guarantee. Current x64 platforms require lock-free uint32/uint64 atomics. Status/diagnostic loads are safe across owners; individual counters are point-in-time observations, not an atomic multi-field snapshot. After `finish`/join the final counts are stable.

Invalid shape/quantum/pointers or noncontiguous/overflowing engine frames latch failure without invented silence or timestamp changes. Pool exhaustion accepts the available prefix, reports the exact rejected suffix, latches `QueueFull`, and preserves unread slabs. Cumulative rejected-frame counts saturate rather than wrap. Nonfinite input samples become zero and are counted; ordinary float overs remain raw. The caller must stop recording on a terminal report and surface the status; an incomplete prefix is not a complete take.

`finish` publishes the last partial slab and releases producer-done. Call it from the audio owner or after callback shutdown transfers ownership. Destroy the pipe only after both owners stop. No live GUI reads of `nextFrame()` are allowed.

## Disk supervisor and publication

`RecordingWorker` creates the writer off RT and starts a separate disk thread (Linux standard thread, Windows Win32 thread). It polls idle input at1 ms; this wait never happens in an audio callback. File writes, hashing, checkpoint flushes and publication run on that thread. `writtenFrames()`/`complete()` are atomic UI-facing observations. Normal shutdown stops callbacks, calls `pipe.finish()`, then `wait()` off RT. Worker exceptions latch an audio-visible writer failure and are rethrown by `wait()`. Cancel/destruction cooperatively joins the worker and retains a checkpoint; cancel does not publish a successful take.

Each recording exclusively creates `media/capture-<asset-UUID>/`. It writes `audio.partial.rf64` as **RF64 IEEE float32** using libsndfile1.2.2, through an exclusively created descriptor with library close ownership disabled. No forced ±1 clamp is enabled. Checkpoint default is one second, rounded up to the next completed slab; explicit intervals are bounded to60 seconds. Raw capture precedes EQ; these files contain no monitoring correction or destructive processor output.

Checkpoint order is: update RF64 header → library flush/error check → OS file flush → flush a unique temporary journal → atomically replace `journal.json` → flush the directory on Linux. Initial media/job directory creation is flushed as well. Incremental SHA-256 covers the committed interleaved little-endian IEEE float32 sample stream; a copied hash state supplies the digest without rereading an ever-growing take. This digest differs intentionally from the final asset's whole-file SHA-256.

Finalization requires stopped/drained input and a nonempty take. Checkpoint, close the library (which can update headers), flush/close the underlying descriptor, publish `take.wav` without replacement, then publish finalized journal state and calculate the whole-file asset hash. Linux uses same-directory hard-link/no-overwrite publication followed by partial-alias removal and directory flush; Windows uses no-replace `MoveFileExW` with write-through and reports file-flushed durability. Filesystem/physical power-loss qualification is not inferred from successful syscalls. Failed flush/publication leaves evidence for explicit recovery and never overwrites a preexisting destination.

## Versioned journal and recovery

Journal1.1 is a bounded16 KiB JSON object, depth≤4, strict expected fields/numeric types, duplicate-key rejection and explicit schema rejection. It records project/track/asset UUIDs, rate/layout, engine-frame start, supplied input latency, committed frames, next sequence, sample digest, phase, capture status, observed rejected/nonfinite counters and optional recovered-from UUID. No external paths or machine-translated identities are stored. S5 adds optional immutable `timingOrigin` (backend, device position, monotonic time, preparation generation, clock ID/cycle, rate fraction and diagnostic driver delay) and `endReason`. Exact1.0 journals decode with absent origin/unknown reason;1.1 uses strict additional fields and typed/ranged integers. Recovery preserves the original origin and records `RecoveredCheckpoint` as the new copy's end reason. Native clock-origin persistence is tested; physical latency/alignment measurement remains open. Neither driver delay nor a supplied numeric latency is measured device alignment.

`inspectRecording` verifies job identity, regular nonlinked files, RF64/float/rate/channel metadata, sufficient readable frames and the entire committed-prefix sample digest with bounded1024-frame read buffers. Header frames beyond the journal checkpoint are reported but excluded from recovery. An older capturing journal can find an already-published final file after interruption; a partial/final hard-link alias is accepted only if both identify the same file. Ambiguous different files fail. Corrupt/truncated prefixes fail rather than silently shorten the requested recovery.

`recoverRecording` verifies the source, copies exactly the committed prefix into a **new UUID/job**, rechecks its sample digest while copying, and finalizes the copy. Original partial/final/journal files remain unchanged. `attachRecording` prepares and validates a model copy before changing the session: raw asset intact, a non-destructive clip shifted by supplied input latency, initial negative timeline alignment represented as a source trim. `ProjectStore.save` persists that edit separately. A finalized take whose project save fails remains discoverable; general recovery discovery/UI/undo is still S6/M2 work.

Directories and ancestors must be owner-controlled, as with existing project storage. These APIs are for owned recording files, not a qualified sandbox/general media importer. Hostile concurrent directory replacement, broad codec parser containment and native filesystem security tests remain part of the full product gates.
