# Portable selected-library snapshot verification

`tools/restoration_library_snapshot_reader.py` verifies retained candidate snapshots without requiring the original selected library files or original selection-file location. Supply explicit source/platform, collection, candidate, report, selection and snapshot-receipt pins. The reader checks the original native dependency report and helper payload through their existing checked readers; it then verifies the retained snapshot's exact schema, file inventory, provenance and complete copied bytes.

The snapshot must contain only `snapshot.json`, `selections.json`, `bindings.json` and the declared ordered `file-NNN.bin` entries. Pending, extra, missing, linked and non-plain entries are refused. The existing 64-file, 64-MiB-per-file, 128-MiB-total and receipt bounds remain. Each name must occur once at most in the checked direct-name inventory. Original selected paths are opaque absolute POSIX or Windows path provenance, including cross-host candidate preparation; no open, stat, resolve, search or load uses those paths. Artifact-relative copied names are checked separately and cannot name outside the snapshot.

The expected binding, context, role lists, unbound names and false authority flags must match exactly. The snapshot binds the retained selection and binding hashes; copied files must match the original selected extents and SHA-256 pins. The tool reads back the reports, provenance and every copied file again before success and rechecks the complete directory inventory. It changes no files and executes no helper or inspector. This remains point-in-time byte consistency, not an atomic filesystem snapshot or authenticity attestation. Producer-computed pins establish consistency; the consumer must supply its intended receipt pins.

The result has format `sc-restoration-library-snapshot-verification-v1`, `snapshotVerified: true` and `originalSourcePathsAccessed: false`. All helper-execution, loader, ABI, licensing, closure/source, package, installer and installed-GUI authority flags stay false. No dependency set, delivered preview, installation lifecycle or frozen workflow parity is promoted.

The CLI requires `--snapshot DIRECTORY --reports DIRECTORY --candidate DIRECTORY --platform linux|win32 --expected-source COMMIT --collection-sha256 PIN --candidate-sha256 PIN --reports-sha256 PIN --selections-sha256 PIN --snapshot-sha256 PIN`. It prints JSON only after the complete check succeeds. Both owning native CI paths retain a separate `restoration-library-snapshot-verification.json` outside the unchanged snapshot inventory. Synthetic tests delete the original selected file and external selection file before API and CLI verification. Actual native execution, original artifact integrity, independent snapshot/proof semantics and current reviews remain merge requirements.
