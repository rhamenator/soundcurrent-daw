# Direct dependency names for restoration helpers

The direct-name inventory consumes the checked 17-file native inspector report set and the staged helper payload with explicit collection, candidate and report receipt pins. It extracts declared library names for each of the four roles and binds the names to the original helper hash and stdout hash. It preserves report order and repeated entries. Linux lookup names retain case; Windows lookup names use ASCII lowercase while the original spelling remains available.

This step supports the observed English `readelf --dynamic --wide` dynamic-table layout and `dumpbin /nologo /dependents` normal-import layout. It checks complete table boundaries, safe bounded basename tokens and per-role name limits. Unsupported, truncated or malformed layouts and unsupported import sections are refused rather than silently omitted. Original reports remain authoritative evidence for information outside this name list. A complete Linux dynamic table with no NEEDED rows yields an empty direct-name list; it does not establish closure or absence of runtime loading. The recognized Windows normal-import layout requires a non-empty import table; other layouts remain refused and unqualified. Broader inspector layouts remain unqualified.

The inventory runs no helper or inspector, performs no library search or load, copies no libraries and changes no report files. Before extraction it checks the pinned report set, checks each stdout's bytes again against its binding, and verifies the report set again afterward. The output is a point-in-time consistency result, not an atomic snapshot, tool authenticity attestation, dynamic-load discovery or transitive dependency closure. Library resolution, versions, packaging classification, dependency source and licensing remain unresolved. All helper-execution, closure/source, standalone/package, installer and installed-GUI authority flags remain false. Default preview application inventories are unchanged.

`tools/restoration_direct_dependencies.py --reports DIRECTORY --candidate DIRECTORY --platform linux|win32 --expected-source COMMIT --collection-sha256 PIN --candidate-sha256 PIN --reports-sha256 PIN` writes the inventory JSON to stdout only after all roles succeed. The owning native Linux and Windows CI paths retain it separately as `restoration-worker-direct-dependencies.json`; it is outside the unchanged report directory. Producer-computed pins show consistency only. Exact-head native execution, all original artifact integrity, independent inventory semantics, available reviews and the existing product qualification gates remain required.
