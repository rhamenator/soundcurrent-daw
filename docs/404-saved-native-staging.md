# Saved native staging owner

SavedRestorationStage is a serialized I/O-only live owner. It consumes and retains
the original native saved audit and a freshly approved source file; no accepted
Session or positive project epoch is fabricated. It binds the original private
source ticket and completed checker report against independently captured current
source context and observed checker PID, performs a fresh full finite decode,
and rechecks that source/report/audit before destination mutation. The fresh
decoded content/audio tuple must also equal the original audit before staging. Its saved
record uses the actual native writer PID and fresh operation, distinct from the
historical operation. Preparation and staging namespaces remain trusted caller
inputs, never permissions reconstructed from the record.

The shared native staging implementation compares its actual held parent stamp
with the original audit stamp before the BeforeDirectory hook and again after
the hook, before exclusive operation creation. A different root or prior root
mutation refuses before operation creation. This is a held-handle check; a path
or copied public stamp alone cannot grant original-audit ownership.

The resulting owner retains the original six audit pins, original immutable
stamp, approved source, planned saved record, native parent/operation/intent/file
handles and their resource scopes. Reverification checks the known owned root
transition, exact planned intent, staged bytes, all original pinned/named facts
and native source again. Cancellation and failures retire admission and native
owners, preserving created partial staging and historical evidence. Ordinary
audit verification remains strict; no original stamp or fingerprint is reset.
Trusted parent writers and existing same-user/non-atomic namespace limitations
remain unchanged. Publication and receipt creation are unavailable through this
owner.

This is a shared Linux/Windows native foundation, tested with actual approved
files and a real reaped checker. It is not yet wired into an isolated saved
staging child or the controller. The process using prepare must be the actual
writer; a future isolated worker must freshly approve the selected source and
use its own native PID. Distinct bounded request framing, original saved-ticket
binding across that process boundary, serialized current controller/preparation
ownership, one-use actual-child publication permission, canonical verification,
explicit Open/adoption and localized recovery controls remain required work.
No prepared DTO or saved record grants any of those capabilities. The old
accepted-project schema and nonzero-epoch policy are unchanged.
