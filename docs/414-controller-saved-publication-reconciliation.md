# Controller saved-publication reconciliation

`ReconcileSavedPublication` is an explicit internal command for a cold controller
that still retains its original ambiguous publication owner. It is not project
opening, automatic adoption, source reopening, publication retry or restart
recovery. The saved publication completion remains historical: a prior unknown
publication stays unknown even when current canonical bytes are verified.

Successful private source preparation now retains an admitted copy of the full
original selected asset, original manifest hash and destination stamp alongside
the original request, ticket and actual checker result. Variable descriptor and
native-evidence storage is precharged before copying; no passive Session becomes
a controller model. Ambiguous publication finish captures context from its actual
IoJob, original source/checker owner and observed child PID under the existing
permission mutex. The checker job and inspection/preparation job are distinct.

Admission requires this retained private owner, its actual publication operation,
current cold epoch/revision and publication/preparation IDs, plus a new monotonic
inspection request. Path, source and restoration overrides are refused. While the
guard is set, only this narrow command, Barrier and exact active inspection
cancellation are accepted; asynchronous shutdown remains available.

The I/O worker uses the separate strict saved-publication audit with expectations
from the private owner, including the actual completed checker's content extent
and hash. It requires the unchanged original manifest and verified current
canonical media. Any receipt must match; missing receipts do not imply historical
absence and do not prevent this current-fact check. Native destination identity
must match the originally recorded object (Linux device/inode or Windows
volume/file index), and the audit rechecks its fresh pinned/named snapshot. The
original pre-publication full stamp is never rebased or reused as publication
authority. This metadata comparison does not reconstruct an exited native owner
or promise atomic protection against hostile concurrent namespace writers.

Final control processing holds the actual publication/cancel/close mutex and
rechecks the private shared owner, captured context, current cold state, exact
inspection owner and canonical result before clearing the current guard and
retiring the retained preparation. Cancellation, close, stale/conflicting evidence
or errors leave the guard unresolved. Closing retires the private preparation
after I/O retirement while preserving honest historical completion observations.

Actual controller/checker/live-child qualification covers successful current
proof with final, partial and missing receipts; unknown historical publication;
checker/preparation job separation; admission refusal, Barrier/stale cancellation
and replay; missing/corrupt canonical media, conflicting receipts and manifest,
replacement destination identity, pinned visibility changes, cancel/close,
exception refusal, repair through a fresh request and private-credit retirement.
An original source path can disappear before fresh reconciliation. Existing
Linux/native Windows execution, review, log/artifact retention and merge gates
remain mandatory; no test deadlines or inventory requirements are reduced.

The explicit strict Open/adoption interaction, localized recovery UI and restart
recovery remain subsequent requirements. This command grants no source or live
publication capability and does not claim full project recovery completion.
